### Step 7 — Test flakiness root cause & fix (commit `6b679a9`)

First re-run of the suite failed: `FAILURES! Tests: 162, Assertions: 456, Failures: 1` — `test_ssrf_gate_blocks_private_ips`.

**Diagnosis chain:** working tree clean → gate passes standalone with debug logging (all 3 hostnames resolve to public IPs, `blocked=0`) → cause: the test did **live internet DNS**, and a transient resolver failure (VPN/filtered networks) made the gate correctly fail-closed → the test, not the gate, was defective.

**Fix (production path untouched):**
- `SsrfGate`: added a resolver seam — `setResolver(?callable)` + private `resolveHost()`; default stays live DNS on both families, fail-closed on empty.
- Test injects deterministic answers (`api.telegram.org`, `api.openai.com`, `example.com` → public IPs; unknown → empty = fail-closed).

**Result:** `OK (162 tests, 458 assertions)`, exit 0 — deterministic, no network dependency.
