## خلاصه

این سند UX پنل ادمین وردپرسیِ ساخت‌یافته با ۱۴ بخش (منطبق با `SPECIFICATION.md:213-226`) و ۱۱ فلوی اصلی (منطبق با `SPECIFICATION.md:241-252`) را تعریف می‌کند. تمام تصمیم‌ها حول یک اصل مرکزی می‌گردد: **کاربرِ غیرفنیِ فارسی‌زبان باید بدون دانش Telegram Bot API یا مدل‌های AI، از نصب تا انتشار، در «کمترین تعداد کلیک و بدون مواجهه با هیچ Secret» به نتیجه برسد.** دو الزام سراسریِ غیرقابل‌مذاکره از اسناد بالادست وارد این سند شده‌اند: (۱) انسان‌در‌حلقه — هیچ پستی بدون Preview و Approve منتشر نمی‌شود (`PRODUCT_SPEC.md:40, 161`؛ `PRODUCT_STRATEGY.md:38`)؛ (۲) امنیت از ابتدا — Token تلگرام و API Key در Frontend/URL/لاگ/پیام خطا ظاهر نمی‌شوند (`SPECIFICATION.md:37-38`).

## ۱. اصول طراحی (Design Principles)

این هفت اصل، مبنای هر تصمیم ظاهری و رفتاری در این سند است و از ویژگی‌های الزامی فاز ۳ (`SPECIFICATION.md:228-237`) و نیاز گروه‌های مشتری اولویت P0 — مدیران کانال و فروشگاه‌ها (`PRODUCT_SPEC.md:62-71`) — به‌همراه پرسونای مرجع P1 (صاحب فروشگاه آنلاین) مشتق شده‌اند (`PRODUCT_SPEC.md:75-82`):

1. **RTL-اول (نه ترجمه‌ی بعدی):** چیدمان، تایپوگرافی، فاصله‌گذاری و جریان خوانش از ابتدا راست‌به‌چپ و فارسی است. هیچ صفحه‌ای «LTR است که بعداً آینه می‌شود» نیست (`PRODUCT_SPEC.md:160`).
2. **سادگی برای غیرفنی:** اصطلاحات فنی (Base URL، Temperature، Max Tokens، Chat ID) پشت برچسب فارسی و بخش «تنظیمات پیشرفته» قابل‌بازشدن مخفی می‌شوند؛ حالت پیش‌فرض همیشه با مقادیر معقول پر می‌شود (`PRODUCT_SPEC.md:81, 115`).
3. **سرعت ادراکی و واقعی:** هیچ فراخوانی API تلگرام/AI روی بارگذاری صفحه‌ی اصلی اجرا نمی‌شود؛ اعداد داشبورد از cache/transient خوانده می‌شوند (مبنای الزام Performance فاز ۱۱: `SPECIFICATION.md:522-533`). اسکلتون (Skeleton) قبل از داده، نه اسپینر بلاتکلیف.
4. **شفافیت وضعیت:** کاربر همیشه می‌داند هر پست «در چه مرحله‌ای» است (Draft → Preview → Approved → Scheduled → Publishing → Published/Failed) با برچسب رنگی فارسی.
5. **انسان‌در‌حلقه:** Approve یک گام صریح و غیرقابل دورزدن است؛ دکمه‌ی انتشار مستقیم بدون تأیید وجود ندارد (`PRODUCT_STRATEGY.md:38`).
6. **امنیت به‌عنوان تجربه:** Secretها همیشه ماسک‌شده‌اند؛ پس از ذخیره هرگز برنمی‌گردند؛ لاگ‌ها و خطاها فقط پیام انسانی + Request ID نشان می‌دهند (`SPECIFICATION.md:37-38, 827-839`).
7. **موبایل‌اول در مواقع بحرانی:** فلوی‌های اصلی (تولید، تأیید، انتشار) باید روی موبایل کامل و بدون اسکرول افقی قابل اجرا باشند، چون مدیر کانال در عمل اغلب با گوشی تأیید می‌کند (**فرض طراحی — U6**؛ مبنای الزام موبایل‌فرندلی `SPECIFICATION.md:234`).

### ۲.۳ گروه‌بندی منو برای کاهش بار شناختی

منوی وردپرسی رسمی پنل به چهار خوشه‌ی معنادار برای کاربر غیرفنی تقسیم می‌شود (ترتیب نمایش، نه تفکیک سخت‌افزاری — در وردپرس همه زیر یک Slug والد `ATA` قرار می‌گیرند):

1. **خلاصه و مدیریت:** داشبورد، پست‌ها، صف محتوا، زمان‌بندی.
2. **تولید:** تولید محتوا با AI، قالب‌ها، پرامپت‌ها.
3. **اتصال‌ها:** کانال‌ها، سرویس‌های AI، رسانه.
4. **پشتیبانی و سیستم:** گزارش‌ها، تنظیمات، لایسنس، راهنما.

ترتیب پیش‌فرض صفحه‌ی فرود پس از نصب = **داشبورد** (یا Setup Wizard در اولین اجرا).

## ۳. سیستم طراحی (Design System)

### ۳.۱ زبان بصری و جهت

- **جهت:** RTL سراسری (`dir="rtl"` + `lang="fa-IR"`). اعداد، تاریخ و زمان با ارقام فارسی؛ مقادیر تکنیکال (مثل Token ماسک‌شده یا Request ID) در حالت LTR خوانا نگه داشته می‌شوند.
- **سبک:** مینیمال، روشن، با کارت‌های سفید روی پس‌زمینه خاکستری روشن؛ سایه کم و شعاع ملایم. زبان بصری «ابزار کاری درون وردپرس» است، نه یک وب‌اپ مستقل شلوغ. (هم‌راستا با انتظار خریدار RTL-Theme از افزونه‌های وردپرسی.)
- **تم تیره:** در MVP الزامی نیست؛ به‌عنوان بهبود V1 ثبت می‌شود و در این سند فقط تضمین می‌شود که رنگ‌ها متغیر (CSS Custom Property) تعریف می‌شوند تا تم تیره پس از MVP اضافه شود بدون تغییر ساختار.

### ۳.۲ تایپوگرافی

- **فونت فارسی:** `Vazirmatn` (پیش‌فرض)، جایگزین: `IRANSans`, `Tahoma`, `sans-serif`. اعداد جدولی (`font-feature-settings: "tnum"`) برای ستون‌های عددی/تاریخ.
- **مقیاس:**
  - عنوان صفحه (H1): ۲۰px / bold
  - عنوان کارت (H2): ۱۶px / 600
  - متن بدنه: ۱۴px / line-height 1.6
  - متن کمکی: ۱۲px
  - دکمه‌ها و لیبل‌ها: ۱۴px / 500
- **حداقل اندازه‌ی لمسی:** ۴۴px (ارتفاع دکمه/ورودی) برای موبایل؛ در دسکتاپ دکمه فشرده ۳۶px مجاز است.

### ۳.۳ رنگ

پالت بر پایه‌ی نسبت کنتراست WCAG AA (حداقل ۴.۵:۱ برای متن) ساخته شده است.

| نقش | رنگ | کاربرد |
| --- | --- | --- |
| برند (Primary) | `#2563EB` (آبی) | دکمه‌های اصلی، لینک‌ها، حالت انتخاب |
| متنی اصلی | `#111827` | متن عنوان و بدنه |
| متنی ثانویه | `#6B7280` | توضیح، متادیتا |
| زمینه | `#F9FAFB` | پس‌زمینه صفحه |
| سطح (سطح کارت) | `#FFFFFF` | کارت‌ها و ورودی‌ها |

- **قاعده کوررنگی:** رنگ هرگز تنها حاملِ معنا نیست؛ هر وضعیت علاوه بر رنگ، یک آیکون و/یا برچسب متنی دارد (مثلاً «منتشر شده ✅» نه فقط نقطه سبز).

### ۳.۴ فاصله و گرید

- واحد پایه **۴px**؛ مقیاس فاصله: ۴، ۸، ۱۲، ۱۶، ۲۴، ۳۲، ۴۸.
- کارت‌ها: padding داخلی ۱۶px، شعاع ۸px، حاشیه ۱px `#E5E7EB`.
- گرید داشبورد: ۱۲ ستونه؛ کارت‌ها دسکتاپ ۳ یا ۴ ستونه، تبلت ۲ ستونه، موبایل ۱ ستونه.

### ۳.۵ کامپوننت‌های پایه

| کامپوننت | مشخصه |
| --- | --- |
| دکمه | سه سطح: Primary (توپُر آبی)، Secondary (حاشیه/خاکستری)، Ghost (متنی)؛ سه حالت: عادی / در حال انجام (اسپینر + غیرفعال) / مخرب (قرمز برای حذف). |
| ورودی متن | با لیبل فارسی، placeholder نمونه، متن راهنما، و آیکون ؟ برای توضیح. |
| ورودی Secret | `type=password` ماسک‌شده + دکمه «نمایش/پنهان»؛ پس از ذخیره، فقط وضعیت «متصل» و ۴ کاراکتر آخر (در صورت لزوم) نمایش داده می‌شود — **هرگز مقدار کامل برنمی‌گردد**. |
| لیست انتخابی (Select) | بومی وردپرس برای سازگاری، با جستجو در لیست‌های بلند (مثلاً مدل‌ها). |

| Toast | گوشه پایین (در RTL چپ یا راست بر اساس قالب) با رنگ وضعیت، محو خودکار ۵ ثانیه، دکمه بستن. |

| Tabs | برای گروه‌کردن تنظیمات (عمومی / پیشرفته). |

### ۳.۶ آیکون‌ها

- آیکون‌های خطی (Line) با وزن یکسان و قابل‌درک بدون متن؛ در کنار هر آیکون منو همیشه لیبل فارسی می‌آید (هیچ آیکون تنها/مبهم).
- آیکون وضعیت: ✓ متصل/منتشرشده، ⚠ هشدار، ✕ خطا، 🕓 زمان‌بندی.
- از آیکون‌های برند Telegram/AI فقط در جای اتصال (نه به‌عنوان جایگزین برچسب) استفاده می‌شود.

## ۴. چیدمان کلی (Global Layout)

### ۴.۱ قاب پنل وردپرسی

- پنل **داخل** داشبورد وردپرس (`/wp-admin`) اجرا می‌شود و هویت ادمین وردپرس را حفظ می‌کند؛ کاربر، منو و راه‌بری بومی وردپرس را می‌شناسد (مطابق انتظار پرسونای P1: `PRODUCT_SPEC.md:78`).
- **هدر هر صفحه:** عنوان فارسی + زیرعنوان یک‌خطی + دکمه‌ی اقدام اصلی سمت چپ (در RTL) مثل «+ پست جدید».
- **نوار وضعیت اتصال (Status Strip):** یک نوار باریک در بالای داشبورد (و قابل‌بازشدن در صفحات دیگر) که خلاصه اتصال‌ها را نشان می‌دهد: «تلگرام: متصل ✓» / «AI: متصل ✓» / «کانال: ۲». کلیک روی هر مورد → صفحه اتصال مربوطه. این نوار، رفع‌کننده‌ی «سردرگمی غیرفنی با وضعیت اتصال» است (`PRODUCT_SPEC.md:115`).

### ۴.۲ ریسپانسیو و موبایل

پنل از چارچوب واکنش‌گرای وردپرس ارث می‌برد، اما قواعد اختصاصی زیر اعمال می‌شود (نقاط شکست در بخش ۸):

- گریدها به یک ستون می‌شوند؛ جدول‌ها به «کارت ردیف» (row-as-card) تبدیل می‌شوند بدون اسکرول افقی.
- دکمه‌های اقدام اصلی به عرض کامل (full-width) با ارتفاع لمسی ۴۴px.
- Setup Wizard موبایل: گام‌ها با پیشرفت خطی بالای صفحه.

### ۴.۳ ناوبری

- منوی اصلی = منوی وردپرس (والد `ATA` + ۱۴ زیرآیتم). ترتیب خوشه‌ای بخش ۲.۳.
- **میان‌برهای متنی (Breadcrumb)** در صفحات عمیق (مثلاً پست → پیش‌نمایش) برای بازگشت.
- **دکمه‌ی بازگشت** واضح در فلوی‌های چندمرحله‌ای.

## ۵. الگوهای سراسری (Global Patterns)

### ۵.۱ وضعیت خالی (Empty State)

هر لیست خالی یک اقدام اولیه پیشنهاد می‌دهد، نه پیام مرده:
- کانال‌ها: «هنوز کانالی متصل نیست» + **[اتصال کانال]**.
- پست‌ها: «اولین پست خود را بسازید» + **[تولید محتوا]**.
- صف: «چیزی در نوبت نیست» + **[زمان‌بندی یک پست]**.

### ۵.۲ بارگذاری و اسکلتون

- در بارگذاری اولیه → Skeleton (جای‌نگهدار شکل واقعی محتوا)، نه اسپینر مبهم.
- در عملیات‌های کوتاه (تولید AI، تست اتصال) → دکمه با اسپینر و متن حال (مثلاً «در حال تولید…»)، غیرفعال برای جلوگیری از ارسال تکراری.
- تولید AI ممکن است طولانی باشد (تا مهلت Timeout): نوار پیشرفت نرم + پیام «این کار ممکن است تا N ثانیه طول بکشد» (مقدار از Timeout خوانده می‌شود، نه عدد ثابت).

### ۵.۳ خطا و هشدار

مطابق مدل خطای ساخت‌یافته (`SPECIFICATION.md:827-839`):
- هر خطای رو به کاربر شامل: **پیام انسانی فارسی** (چه شد + چه کنم) + **کد خطا + Request ID** (برای تیکت پشتیبانی) + **دکمه اقدام** (تلاش مجدد / بررسی اتصال).
- خطای فنی لایو (trace، body پاسخ، Secret) **هرگز** به کاربر نشان داده نمی‌شود؛ در Logs با سطح Developer و Secretهای redact‌شده ذخیره می‌شود.
- خطاهای پیش‌بینی‌شده، پیام اختصاصی دارند (نه رشته خام): Token نامعتبر، Rate Limit (۴۲۹)، Timeout، Bot در کانال ادمین نیست، API Key نامعتبر.

### ۵.۴ تأیید و پیام (Confirmation)

- اعمال مخرب (حذف پست، لغو زمان‌بندی، قطع اتصال کانال/AI، برداشتن کلید) همیشه یک Modal تأیید با دکمه مخرب می‌خواهند.
- اعمال برگشت‌پذیر و کم‌ریسک (ذخیره پیش‌نویس) یک Toast تأیید ساده می‌گیرند.

### ۵.۵ امنیت نمایش Secret (قانون ۱۳ و ۱۴)

- ورودی Token/API Key → `type=password` با toggle نمایش؛ پس از ذخیره، فیلد خالی/ماسک‌شده می‌ماند و وضعیت «متصل» جایگزین می‌شود.
- هیچ Secret در URL (query string)، HTML منبع، JS، لاگ یا Toast ظاهر نمی‌شود (`SPECIFICATION.md:37-38`).
- دکمه‌های «تغییر کلید» و «قطع اتصال» جدا هستند تا کاربر لازم نباشد کلید قبلی را ببیند.

### ۵.۶ زبان غیرفنی (Content-first)

هر اصطلاح فنی یک ترجمه‌ی انسانی دارد؛ جزئیات فنی در «تنظیمات پیشرفته» با توضیح ابزارک ثبت می‌شود:

| اصطلاح فنی | برچسب کاربر | توضیح ابزارک (؟) |
| --- | --- | --- |
| Bot Token | کلید ربات تلگرام | از @BotFather دریافت می‌شود؛ لینک راهنما |
| API Key | کلید اتصال AI | از پنل سرویس‌دهنده AI شما |
| Base URL | آدرس سرور (پیشرفته) | فقط اگر سرویس‌دهنده آدرس اختصاصی داده است |
| Model | مدل | مدل‌های آماده از سرویس‌دهنده لیست می‌شوند |
| Temperature | خلاقیت | ۰ = دقیق و قابل‌پیش‌بینی، ۱ = خلاق‌تر |
| Max Tokens | طول پاسخ | حداکثر طول متن تولیدی |
| Timeout | مهلت پاسخ | حداکثر زمان انتظار برای پاسخ |
| Chat ID | شناسه کانال (پیشرفته) | فقط برای اتصال دستی؛ روش ساده: انتخاب از لیست |

## ۶. مشخصات صفحه‌ها (۱۴ بخش)

برای هر صفحه: **هدف**، **کامپوننت‌های اصلی**، **اقدامات**، **حالت‌ها**، **یادداشت اسکوپ/موبایل**.

### ۶.۱ داشبورد (Dashboard)

- **هدف:** نمای یک‌نگاهه از «وضعیت حساب» برای کاربر غیرفنی؛ اولین صفحه پس از Setup.
- **کارت‌های عددی:** کانال‌های متصل، پست‌های این هفته، در نوبت (صف)، مصرف AI (تعداد درخواست در این دوره — بدون قیمت، چون هزینه BYOK است و اعداد هزینه در شواهد ثبت‌شده موجود نیستند).
- **نوار وضعیت اتصال** (بخش ۴.۱) همیشه بالای داشبورد.
- **اقدامات سریع:** [تولید محتوا] و [زمان‌بندی پست].
- **فعالیت اخیر:** ۵ رویداد آخر از Logs با پیام انسانی.
- **اگر Setup ناقص باشد:** بنر راهنما «برای شروع، اتصال تلگرام را کامل کنید» + دکمه ادامه.
- **عملکرد:** اعداد از cache/transient، نه API زنده (`SPECIFICATION.md:522-533`).

### ۶.۲ کانال‌ها (Channels)

- **هدف:** اتصال، فهرست و وضعیت کانال‌های تلگرام.
- **اجزا:** جدول/کارت کانال‌ها با نام، شناسه (نیمه‌ماسک یا کاربرگشا)، تعداد (در صورت موجود بودن از Telegram)، وضعیت (متصل/خطا)، دکمه‌های [تست اتصال]، [قطع اتصال].
- **اقدام اصلی:** [+ اتصال کانال] → فلوی ۷.۵.
- **حالت‌ها:** خالی (بخش ۵.۱)؛ «Bot در کانال ادمین نیست» با راهنمای دوخطی.

### ۶.۳ پست‌ها (Posts)

- **هدف:** فهرست و چرخه حیات همه پست‌ها.
- **اجزا:** فیلتر بر اساس وضعیت، جستجو، جدول با ستون‌ها (عنوان/خلاصه، کانال، وضعیت، زمان‌بندی، اقدام).
- **وضعیت‌ها (Badge):** پیش‌نویس، در بازبینی، تأییدشده، زمان‌بندی‌شده، در حال انتشار، منتشرشده، خطا.
- **اقدامات سطری:** مشاهده/ویرایش، پیش‌نمایش، برنامه‌ریزی، حذف (با تأیید).
- **حالت موبایل:** ردیف‌ها به کارت با دکمه‌های stacked.

### ۶.۴ تولید محتوا با AI (AI Generator) — هسته محصول

- **هدف:** گلوگاه تولید محتوا را حذف کند (`PRODUCT_SPEC.md:112`)؛ کامپوزر دو ناحیه‌ای.
- **ناحیه ورودی (راست در RTL):**
  - **انتخابگر عملیات** (Segmented): تولید / بازنویسی / خلاصه / عنوان / کپشن / ترجمه (`SPECIFICATION.md:414-422`).
  - **کانال هدف** (اختیاری برای تولید آزاد، الزامی برای انتشار).
  - **موضوع/متن ورودی:** با placeholder فارسی («درباره چه چیزی بنویسم؟»).
  - **تُن** (در MVP لیست کوتاه از تُن‌های زیرمجموعه، کامل ۱۰ تُن در V1 — `SPECIFICATION.md:381-391`).
  - **زبان و طول** ترجیحی.
  - **[تولید]** (Primary).
- **ناحیه خروجی (چپ):** نتیجه با حالت ویرایش درجا (Edit in place)، دکمه‌های [بازتولید]، [کپی]، [افزودن تصویر]، [ذخیره پیش‌نویس]، [پیش‌نمایش].
- **حالت‌ها:** تولید (اسپینر + «در حال تولید…»)، خطای AI با Request ID و Retry، خالی.
- **موبایل:** دو ناحیه به دو گام پشت‌سرهم تبدیل می‌شود (ورودی → نتیجه) برای جلوگیری از دیدن نیمه‌کاره.

### ۶.۵ صف محتوا (Content Queue)

- **هدف:** شفافیت وضعیت پست‌های در نوبت/در حال ارسال.
- **اجزا:** فهرست زمانی با وضعیت، زمان اجرای بعدی، تعداد تلاش (Retry count) و اقدامات [اجرای فوری]، [لغو].
- **وضعیت‌ها:** در نوبت، در حال ارسال، تلاش مجدد، خطا، ارسال‌شده.
- **اسکوپ:** پایداری ۵۰+ پست و Crash Recovery در V1 (`SPECIFICATION.md:449-472`؛ `PRODUCT_STRATEGY.md:148`)؛ در MVP صف با Retry/Cancel ساده است.

### ۶.۶ زمان‌بندی (Scheduler)

- **هدف:** انتخاب تاریخ/زمان انتشار (بر اساس Timezone وردپرس).
- **اجزا:** انتخابگر تاریخ/زمان (تقویم فارسی + ذکر صریح timezone سایت برای جلوگیری از خطای ساعت)، لیست زمان‌بندی‌های فعال.
- **اسکوپ:** زمان‌بندی تک‌باره (One-time) در MVP؛ زمان‌بندی تکرارشونده خارج از اسکوپ (بدون ارزش ثبت‌شده در `PRODUCT_STRATEGY.md` — وارد نمی‌شود تا از Feature Creep جلوگیری شود، قانون ۷: `SPECIFICATION.md:31`).

### ۶.۷ قالب‌ها (Templates) — V1

- **هدف:** ساخت محتوای قالب‌دار با متغیر (برای مُدرّس و فروشگاه، پرسونای P3: `PRODUCT_SPEC.md:92-97`).
- **اجزا:** فهرست قالب‌ها (نام، توضیح، تُن)، ویرایشگر قالب با متغیرهای `{{topic}}`, `{{channel_name}}`, `{{title}}`, `{{content}}`, `{{language}}`, `{{tone}}` (`SPECIFICATION.md:372-378`)، پیش‌نمایش با مقادیر نمونه.
- **اسکوپ:** کامل در V1 (`PRODUCT_STRATEGY.md:147`).

### ۶.۸ پرامپت‌ها (Prompts) — V1

- **هدف:** مدیریت تُن‌ها و دستورهای System/User و دستورهای اختصاصی (Custom Instructions).
- **اجزا:** کتابخانه ۱۰ تُن (`Professional, Friendly, News, Marketing, Luxury, Educational, Technical, Creative, Short, Persuasive` — `SPECIFICATION.md:381-391`)، ویرایش System Prompt / User Prompt / Custom Instructions، دکمه بازنشانی به پیش‌فرض.

### ۶.۹ سرویس‌های AI (AI Providers)

- **هدف:** اتصال Provider-Agnostic با BYOK (`SPECIFICATION.md:326-352`؛ `PRODUCT_STRATEGY.md:36-37`).
- **اجزا:** فهرست Providerها + [افزودن سرویس]. فرم: نام، آدرس سرور، کلید اتصال (ماسک)، مدل‌ها، خلاقیت، طول پاسخ، مهلت پاسخ، Headers — موارد پیشرفته در بخش «تنظیمات پیشرفته» جمع‌شونده.
- **اقدامات:** [تست اتصال] (پاسخ را با پیام انسانی و Request ID نشان می‌دهد)، [پیش‌فرض شدن] برای انتخاب Provider فعال، [قطع اتصال].
- **امنیت:** کلید فقط یک‌بار وارد و هرگز بازگردانده نمی‌شود (بخش ۵.۵).

### ۶.۱۰ رسانه (Media)

- **هدف:** کتابخانه تصاویر برای پست‌ها.
- **MVP:** آپلود تصویر + کپشن + انتخاب هنگام ساخت پست (ارسال Image در MVP است: `SPECIFICATION.md:409`).
- **V2:** کتابخانه پیشرفته (`PRODUCT_STRATEGY.md:163`).

### ۶.۱۱ گزارش‌ها / لاگ (Logs)

- **هدف:** شفافیت و دیباگ بدون نشت Secret.
- **اجزا:** جدول: زمان، ناحیه (تلگرام/AI/صف/سیستم)، سطح (اطلاعات/هشدار/خطا)، پیام انسانی، Request ID، [جزئیات] (سطح Developer با redact کامل Secret — `SPECIFICATION.md:839`).
- **فیلترها:** ناحیه، سطح، بازه زمانی. [پاک‌کردن] با تأیید.

### ۶.۱۲ تنظیمات (Settings)

- **اجزا:** عمومی (timezone، قالب تاریخ، تُن/زبان پیش‌فرض) + پیشرفته (تنظیمات صف و Retry — در V1 سخت می‌شود: `PRODUCT_STRATEGY.md:148`).
- **اصل:** پیش‌فرض‌های معقول؛ کاربر غیرفنی بدون لمس تنظیمات هم باید کار کند.

### ۶.۱۳ لایسنس (License)

- **اجزا:** ورودی کلید لایسنس (ماسک‌شده)، وضعیت فعال‌سازی (فعال/غیرفعال)، دامنه، اعتبار.
- **حالت‌ها:** کلید نامعتبر → پیام انسانی + راهنمای تماس؛ فعال‌سازی آفلاین (در صورت خطا) → Request ID برای پشتیبانی.
- **اسکوپ:** فعال‌سازی در MVP؛ Update Check در V1/فاز ۱۵ (`SPECIFICATION.md:629-644`).

### ۶.۱۴ راهنما (Help)

- **اجزا:** راهنمای شروع (گام‌به‌گام، زیرمجموعه ۱۱ فلو)، پرسش‌های پرتکرار (FAQ)، **تشخیص وضعیت اتصال** (کادر سبز/قرمز برای هر اتصال + دکمه رفع)، مرجع کد خطا، لینک مستندات.
- **هدف:** کاهش بار پشتیبانی و رفع سردرگمی غیرفنی (`PRODUCT_SPEC.md:115`).

## ۷. فلوی‌های اصلی (۱۱ فلو)

قالب هر فلو: **هدف → پیش‌نیاز → گام‌ها (شماره‌گذاری: اقدام کاربر → رفتار سیستم) → تصمیم/شاخه → خطاها → یادداشت موبایل.**

### ۷.۱ فلو — نصب (Install)

- **هدف:** نصب و فعال‌سازی افزونه؛ ورود به Setup.
- **پیش‌نیاز:** فایل ZIP افزونه از RTL-Theme.
- **گام‌ها:**
  1. کاربر: پیشخوان وردپرس → افزونه‌ها → افزودن → بارگذاری افزونه → انتخاب ZIP.
  2. سیستم: نصب و نمایش «فعال‌سازی».
  3. کاربر: [فعال‌سازی].
  4. سیستم: بررسی سازگاری → موفق → redirect به Setup Wizard (۷.۲).
- **خطاها:** ناسازگاری PHP/WP → پیام انسانی «این افزونه به وردپرس X و PHP Y نیاز دارد» (نه خطای خام)؛ خطای فایل ZIP → پیام وردپرس استاندارد.
- **موبایل:** نصب معمولاً دسکتاپ است؛ Setup بعدی موبایل‌فرندلی است.

### ۷.۲ فلو — Setup (راه‌اندازی اولیه / Wizard)

- **هدف:** رساندن کاربر از صفر به اولین وضعیت آماده‌کار در چند گام قابل پرش.
- **پیش‌نیاز:** افزونه فعال.
- **گام‌ها (Wizard با Stepper):**
  1. **خوش‌آمد:** یک‌خط ارزش («تولید → تأیید → زمان‌بندی → انتشار، همه در این پنل») + [شروع].
  2. **بررسی پیش‌نیازها:** چک‌لیست server (green/red)؛ موارد قرمز با توضیح انسانی.
  3. **اتصال تلگرام:** (فلوی ۷.۳ به‌صورت توکار)؛ قابل پرش با «بعداً».
  4. **اتصال AI:** (فلوی ۷.۴)؛ قابل پرش.
  5. **اتصال کانال:** (فلوی ۷.۵)؛ قابل پرش.
  6. **پایان:** خلاصه وضعیت + [رفتن به داشبورد].
- **تصمیم:** هر گامِ پرش‌شده در داشبورد به‌صورت بنر «ادامه تنظیمات» باقی می‌ماند؛ Wizard یک‌بار اجرا می‌شود و از Settings/Help دوباره باز می‌شود.
- **موبایل:** Stepper خطی بالای صفحه، هر گام یک صفحه کامل.

### ۷.۳ فلو — اتصال Telegram

- **هدف:** ثبت Bot Token و برقراری اتصال.
- **گام‌ها:**
  1. کاربر: صفحه «کانال‌ها» یا Wizard → وارد کردن «کلید ربات تلگرام» (ماسک‌شده).
  2. کاربر: [اتصال].
  3. سیستم: فراخوانی شناسایی ربات (بدون نمایش Secret) → موفق → نمایش نام/نام‌کاربری ربات + وضعیت «متصل ✓».
- **خطاها:** Token نامعتبر → «کلید معتبر نیست؛ آن را از @BotFather دوباره کپی کنید» + Request ID؛ خطای شبکه/Rate Limit → «تلگرام موقتاً پاسخ نداد» + [تلاش مجدد].
- **امنیت:** Token هرگز به عنوان Value برنمی‌گردد (بخش ۵.۵).

### ۷.۴ فلو — اتصال AI

- **هدف:** ثبت Provider سازگار با OpenAI (BYOK) و تست آن.
- **گام‌ها:**
  1. کاربر: [+ افزودن سرویس] → نام + آدرس سرور + کلید اتصال (+ در صورت نیاز مدل/خلاقیت/طول/مهلت در پیشرفته).
  2. کاربر: [تست اتصال].
  3. سیستم: درخواست آزمایشی (بدون ثبت Secret در لاگ) → موفق → نمایش مدل‌های در دسترس + [پیش‌فرض کردن].
- **خطاها:** کلید نامعتبر → پیام انسانی؛ آدرس سرور نادرست → هشدار + Request ID (ارزیابی SSRF در معماری/امنیت، فازهای ۴ و ۱۰)؛ Timeout → پیام مهلت.
- **یادداشت:** حالت پیش‌فرض فرم، کاربر را فقط «نام + آدرس + کلید» می‌پرسد؛ باقی در پیشرفته.

### ۷.۵ فلو — اتصال Channel

- **هدف:** اتصال کانال به ربات (ربات باید ادمین کانال باشد).
- **گام‌ها:**
  1. کاربر: [+ اتصال کانال] → انتخاب از لیست کانال‌های در دسترس ربات (روش ساده) **یا** ورود دستی شناسه (پیشرفته).
  2. سیستم: برقراری اتصال و تست ارسال بی‌صدا → وضعیت «متصل ✓».
- **خطاها:** «ربات ادمین کانال نیست» → راهنمای دوخطی («به کانال بروید → تنظیمات → مدیران → افزودن ربات به‌عنوان مدیر»)؛ کانال یافت نشد → پیام انسانی.
- **موبایل:** انتخاب از لیست با جستجو.

### ۷.۶ فلو — ساخت محتوا

- **هدف:** تولید محتوای پیش‌نویس توسط AI (شش عملیات).
- **گام‌ها (در صفحه تولید):**
  1. کاربر: انتخاب عملیات (تولید/بازنویسی/…) + کانال + موضوع/متن + تُن + زبان/طول.
  2. کاربر: [تولید].
  3. سیستم: نشانگر «در حال تولید…» → بازگشت نتیجه در ناحیه خروجی.
  4. کاربر: ویرایش درجا، [بازتولید]، [افزودن تصویر]، [ذخیره پیش‌نویس] یا رفتن به [پیش‌نمایش].
- **تصمیم:** مسیر بعدی پیش‌نویس → پیش‌نمایش (۷.۷).
- **خطاها:** خطای AI → پیام انسانی + Request ID + [تلاش مجدد].
- **موبایل:** دو گام (ورودی → نتیجه).

### ۷.۷ فلو — Preview (پیش‌نمایش)

- **هدف:** مشاهده پست دقیقاً همان‌گونه که در تلگرام نمایش داده می‌شود، قبل از هر تأییدی.
- **گام‌ها:**
  1. کاربر: [پیش‌نمایش] از کامپوزر یا پست.
  2. سیستم: رندر بند‌به‌بند (متن + تصویر + کپشن) در یک قاب شبیه‌ساز تلگرام با نام کانال هدف و ذکر RTL؛ اگر زمان‌بندی شده، زمان نمایش داده می‌شود.
  3. کاربر: یکی از [بازگشت به ویرایش] / [تأیید (Approve)].
- **موبایل:** پیش‌نمایش تمام‌عرض؛ دکمه‌ها ثابت پایین صفحه (sticky) برای دسترسی با انگشت.

### ۷.۸ فلو — Approve (تأیید انسانی) — Gate غیرقابل دورزدن

- **هدف:** تأیید صریح انسان قبل از انتشار (هسته تمایز: `PRODUCT_SPEC.md:161`).
- **گام‌ها:**
  1. سیستم (پس از Preview): دکمه [تأیید و ادامه].
  2. سیستم: انتقال وضعیت Draft → Approved با Badge سبز.
  3. کاربر: انتخاب مسیر — [انتشار الآن] (فلوی ۷.۱۰) یا [زمان‌بندی] (فلوی ۷.۹).
- **قاعده:** هیچ دکمه‌ای مسیر انتشار را بدون عبور از Approve باز نمی‌کند (`PRODUCT_STRATEGY.md:38`).
- **تصمیم:** در صورت نیاز تغییر → [بازگشت به ویرایش] که وضعیت را به Draft برمی‌گرداند.

### ۷.۹ فلو — Schedule (زمان‌بندی)

- **هدف:** قرار دادن پست تأییدشده در صف انتشار با تاریخ/زمان.
- **گام‌ها:**
  1. کاربر: انتخاب تاریخ/زمان (تقویم فارسی + نمایش صریح timezone سایت).
  2. کاربر: [برنامه‌ریزی].
  3. سیستم: افزودن به صف → Toast «پست در نوبت قرار گرفت» + نمایش موقعیت در صف.
- **تصمیم:** می‌تواند مستقیم از Preview پس از Approve فراخوانی شود.
- **خطاها:** تاریخ گذشته → هشدار پیش‌گیرانه قبل از ذخیره.

### ۷.۱۰ فلو — Publish (انتشار)

- **هدف:** ارسال واقعی به کانال (فوری یا از صف) با مدیریت خطا.
- **گام‌ها:**
  1. سیستم (فوری پس از Approve، یا اجرای خودکار صف): وضعیت «در حال انتشار».
  2. سیستم: ارسال به Telegram (متن/تصویر+کپشن).
  3. سیستم: موفق → وضعیت «منتشرشده» + لینک پست تلگرام.
- **خطاها:** Rate Limit (۴۲۹) → انتظار و تلاش مجدد خودکار با شمارنده؛ Token نامعتبر در لحظه ارسال → وضعیت «خطا» + پیام انسانی + [تلاش مجدد]؛ خطای تصویر → پیام خطای انسانی.
- **امنیت:** هیچ Secret در گزارش موفقیت/خطا (بخش ۵.۵).

### ۷.۱۱ فلو — مشاهده نتیجه

- **هدف:** بستن حلقه — دیدن نتیجه و ثبت آن برای کاربر.
- **گام‌ها:**
  1. سیستم (پس از انتشار موفق): صفحه نتیجه: «پست با موفقیت منتشر شد» + [مشاهده در تلگرام] + گزینه‌های [ساخت پست مشابه] / [بازگشت به داشبورد].
  2. سیستم: به‌روزرسانی داشبورد (شمارنده پست)، پست‌ها (Badge منتشرشده)، و Logs (پیام انسانی).
- **موبایل:** صفحه نتیجه با دکمه‌های full-width.

## ۹. دسترس‌پذیری (Accessibility)

- کنتراست WCAG AA (پالت بخش ۳.۳ تنظیم شده است).
- ناوبری کامل با صفحه‌کلید (Tab/Enter/Escape)، فوکوس‌حلقه قابل‌مشاهده.
- لیبل واقعی برای هر فرم، `aria-*` برای وضعیت‌ها و Toastها (مبنای الزام UI فاز ۱۲).
- رنگ تنها حامل معنا نیست (آیکون/متن همراه دارد) — بخش ۳.۳.
- هدف لمسی ≥ ۴۴px در موبایل.

## ۱۰. عملکرد (Performance UX)

- بدون فراخوانی API تلگرام/AI در بارگذاری صفحه؛ اعداد از cache/transient (`SPECIFICATION.md:522-533`).
- Lazy loading تصاویر رسانه؛ pagination برای پست‌ها و لاگ‌ها.
- عملیات طولانی (تولید AI، ارسال) بازخورد فوری (اسپینر در دکمه + نوار پیشرفت) دارد تا «سریع» حس شود (`SPECIFICATION.md:230`).
