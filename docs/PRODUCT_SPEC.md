## ۱. خلاصه اجرایی

AI Telegram Admin یک **افزونه (Plugin) قابل نصبِ وردپرس، خودمیزبان (Self-Hosted) و قابل فروش** است که مدیریت کانال‌ها و محتوای تلگرام را با کمک هوش مصنوعی به یک جریان کاری واحد تبدیل می‌کند:

**تولید محتوا → پیش‌نمایش → تأیید → زمان‌بندی → انتشار → ثبت نتیجه**

مشتری این محصول انسانی **غیر فنی** است که یک یا چند کانال تلگرام را اداره می‌کند (فروشگاه، رسانه، خبری، آموزشی، تولیدکننده محتوا) یا آژانسی که کانال مشتریانش را مدیریت می‌کند. ارزش اصلی، حذف گلوگاهِ تولید محتوا و یک‌جا کردن ابزارهای پراکنده در یک پنل وردپرسی RTL و فارسی‌زبان است؛ نه ساختن «باز هم یک ربات چت».

این سند فقط **تعریف محصول و تصمیم‌های اسکوپ** است. قیمت‌گذاری نهایی، مقایسه‌ی دقیق با رقبا و هر عدد بازار، صریحاً به فازهای ۱ (تحقیق بازار، قانون ۱۰ و ۱۲) و ۲ (استراتژی محصول) واگذار می‌شود و در این سند «unconfirmed» ثبت شده است.

## ۲. تعریف دقیق محصول

### ۲.۱ محصول چیست

یک **نرم‌افزار قابل نصب روی وردپرس** (نه سرویس SaaS ماهانه) که سه لایه‌ی مجزا ولی یکپارچه دارد:

1. **لایه تلگرام** — اتصال Bot Token، مدیریت کانال، ارسال پست (متن و تصویر)، زمان‌بندی و انتشار، مدیریت خطا و Rate Limit. (مبنای فاز ۵: `SPECIFICATION.md:292-324`)
2. **لایه AI** — اتصال به هر سرویس سازگار با OpenAI (Base URL، API Key، Model، Temperature، Max Tokens، Timeout، Headers)؛ کاملاً Provider-Agnostic. تولید/بازنویسی/خلاصه‌سازی/عنوان/کپشن/ترجمه. (مبنای فاز ۶ و ۷: `SPECIFICATION.md:326-395`)
3. **لایه Content & Scheduler** — چرخه Draft → Preview → Edit → Approve → Publish، به‌همراه صف زمان‌بندی، Retry، Cancel و داشبورد. (مبنای فاز ۸: `SPECIFICATION.md:397-447`)

نتیجه نام‌گذاری موقت در `README.md:33` حفظ می‌شود: Namespace کد `ATA` (AI Telegram Admin) تا تعیین نام نهایی برند.

### ۲.۲ محصول چیست (ویژگی‌های ذاتی)

- **پنل مدیریت وردپرسی RTL و ریسپانسیو** برای کاربر غیر فنی (مبنای فاز ۳: `SPECIFICATION.md:207-254`).
- **انسان در حلقه** (Human-in-the-loop): هیچ پستی بدون Preview و Approve منتشر نمی‌شود؛ AI پیشنهاد می‌دهد، انسان تأیید می‌کند.
- **امنیت از ابتدا** (قانون ۱۴): Token تلگرام و API Key سرویس AI هرگز در Frontend/URL/لاگ/پیام خطا ظاهر نمی‌شوند (قانون ۱۳).
- **قابل فروش و قابل نصب در لحظه**: هدف نهایی «محصول قابل فروش در RTL-Theme»، نه Demo (قانون ۲۰).
- **Modular و Extensible**: تلگرام و AI از منطق تجاری جداست؛ افزودن Provider جدید نباید Core را عوض کند (`SPECIFICATION.md:279-287`, `352`).

### ۲.۳ محصول چه نیست (مرز صریح جهت جلوگیری از Feature Creep)

- **ربات چت/گفتگوی هوشمند** با قابلیت مکالمه آزاد با اعضا نیست. محصول «مدیریت کانال و محتوا» است، نه «چت‌بات پشتیبانی».
- **درگاه پرداخت داخل تلگرام / فروشگاه آنلاین داخل ربات** نیست.
- **CRM / قیف عضویت / ابزار رشد فالوور** نیست.
- **اپلیکیشن موبایل مستقل (Native)** نیست؛ پنل وردپرسی موبایل‌فرندلی است.
- **ابزار ارسال انبوه / دایرکت پیام (Bulk DM / Spam Sender)** نیست — این حوزه از ابتدا خارج از اسکوپ است و ساخته نخواهد شد.
- **فروشنده/آموزش‌دهنده مدل AI** نیست؛ مشتری API Key خودش (BYOK) را می‌آورد.

این فهرست در بخش ۱۲ به‌طور کامل به «مرز Feature Creep» متصل می‌شود.

## ۳. مشتری هدف (Target Customer)

تحلیل هشت گروه خواسته‌شده در فاز ۰ (`SPECIFICATION.md:99-108`) بر اساس تناسب با «ارزش اصلی = مدیریت کانال + تولید محتوا + زمان‌بندی»:

| # | گروه | مشکل محوری | تناسب با محصول | اولویت |
| --- | --- | --- | --- | --- |
| ۱ | **مدیران کانال تلگرام** | تولید مستمر محتوا + زمان‌بندی دستی | بسیار بالا (هسته) | P0 |
| ۲ | **کانال‌های فروش / فروشگاه‌ها** | کپشن/عنوان محصول، انتشار منظم، چند کانال | بسیار بالا (تمایل به پرداخت قوی) | P0 |
| ۳ | **رسانه‌ها و کانال‌های خبری** | حجم بالا + سرعت + خلاصه‌سازی + ترجمه | بالا | P1 |
| ۴ | **کانال‌های آموزشی** | تولید محتوای بلند/منظم با تُن ثابت | بالا | P1 |
| ۵ | **تولیدکنندگان محتوا** | تنوعِ تُن، صرفه‌جویی در وقت، برنامه‌ریزی | متوسط–بالا (کشف خودکار، بودجه‌ی محدودتر) | P1 |
| ۶ | **آژانس‌های دیجیتال مارکتینگ** | مدیریت چند کانال مشتری + گزارش + تمرکز | بالا برای V2 (نیازمند چند-کاربری و گزارش) | P2 (V2) |

**تصمیم تجاری (دلیل):** دو گروه P0 (مدیران کانال و کانال‌های فروش/فروشگاه) هسته MVP را می‌سازند چون (الف) مستقیم با چرخه «تولید → تأیید → زمان‌بندی → انتشار» درگیرند و (ب) دردِ تولید محتوا برای آن‌ها هزینه‌ی واقعی و روزانه دارد، پس بیشترین تمایل به خرید یک‌باره را دارند. گروه‌های رسانه/خبری و آموزشی P1 هستند (نیازمند خلاصه‌سازی و ترجمه که در MVP پایه وجود دارد). آژانس‌ها P2 هستند، چون ارزش کامل آن‌ها به چند-کاربری و گزارش نیاز دارد که عمداً به V2 منتقل شد تا MVP منفجر نشود (قانون ۸).

## ۴. پرسوناهای کاربر (User Personas)

### پرسونای P1 — «صاحب فروشگاه آنلاین»
- **نام نمونه:** رضا، ۳۴ ساله، مدیر یک برند پوشاک و دو کانال تلگرام (فروش + اعلان تخفیف).
- **مهارت فنی:** پایین؛ وردپرس را می‌شناسد، نه Telegram Bot API و نه مدل‌های AI.
- **هدف:** هر روز ۳ تا ۵ پست منظم و حرفه‌ای بدون استخدام نیرو؛ کپشن‌های فروش جذاب.
- **درد:** تولید کپشن زمان‌بر است؛ فراموش می‌کند پست بگذارد؛ بین چند ابزار سردرگم است.
- **محرک خرید:** «همه‌چیز داخل وردپرس خودم، یک‌باره بخرم، کلید API خودم را بزنم و تمام.»
- **مانع:** ترس از پیچیدگی نصب؛ نگرانی از هزینه‌ی مخفی AI.

### پرسونای P2 — «مدیر رسانه/خبر»
- **نام نمونه:** سارا، ۴۰ ساله، مدیر یک رسانه با کانال خبری پرمخاطب و تیم کوچک.
- **مهارت فنی:** متوسط؛ گردش کار مشخصی دارد و به «تأیید قبل از انتشار» حساس است.
- **هدف:** انتشار سریع اخبار با خلاصه‌سازی و ترجمه، بدون خطای ارسال.
- **درد:** حجم بالا؛ نیاز به تایید سردبیر؛ پست‌های تکراری/اشتباه.
- **محرک خرید:** جریان تأیید (Approve) + زمان‌بندی دقیق + خلاصه‌سازی/ترجمه.

### پرسونای P3 — «تولیدکننده محتوا / مدرس»
- **نام نمونه:** امید، ۲۸ ساله، مدرس آنلاین با یک کانال آموزشی فارسی.
- **مهارت فنی:** متوسط؛ به تُن و پیوستگی محتوا اهمیت می‌دهد.
- **هدف:** محتوای آموزشی منظم (هفتگی) با تُن ثابت و صرفه‌جویی در زمان.
- **درد:** تنوع تُن، پرامپت‌های تکراری، برنامه‌ریزی دستی.
- **محرک خرید:** موتور پرامپت با تن‌های آماده (Educational, Friendly و غیره) و متغیرها.

### پرسونای P4 — «آژانس دیجیتال مارکتینگ» (اسکوپ V2)
- **نام نمونه:** مهدی، ۳۶ ساله، مدیر آژانس با ۱۰+ کانال مشتری.
- **مهارت فنی:** بالا.
- **هدف:** مدیریت متمرکز چند کانال، گزارش به مشتری، چند کاربر/نقش.
- **درد:** پراکندگی، نبود گزارش، نبود سطح دسترسی.
- **محرک خرید:** چند-کانالی، نقش‌ها و گزارش — که عمداً به V2 منتقل شد.

## ۵. مشکلات (Problems)

مشکلاتی که محصول حل می‌کند (برگرفته از اسکوپ فاز ۰ و ویژگی‌های فاز ۳ و ۸):

1. **گلوگاه تولید محتوا:** نوشتن روزانه پست، عنوان و کپشن زمان‌برترین بخش کار ادمین است. (منطبق با AI Generator فاز ۳ و Generate/Rewrite/Summarize/title/caption/translate فاز ۸)
2. **خیلی از کارها دستی و پراکنده است:** تولید در یک ابزار، زمان‌بندی در ابزار دیگر، ارسال در تلگرام — هیچ‌کدام داخل وردپرس خود کاربر نیست.
3. **وابستگی به وقت‌های خاص:** انتشار در ساعت پیک نیازمند حضور دستی است؛ Schedule/Queue این را حل می‌کند.
4. **خطر خطا در انتشار مستقیم:** بدون Preview/Approve، پست اشتباه یا ناقص منتشر می‌شود.
5. **سردرگمی کاربر غیر فنی با Telegram Bot API و تنظیمات AI:** اتصال Provider با Base URL/Key/Model پیچیده به نظر می‌رسد؛ محصول باید آن را به فرم ساده تبدیل کند.
6. **نگرانی امنیتی/حریم خصوصی:** کاربر نمی‌خواهد Token/Key در معرض دید یا لاگ قرار گیرد. (قانون ۱۳ و ۱۴)
7. **هزینه‌ی استخدامی یا سرویس ماهانه‌ی گران:** کاربر یک ابزار خودمیزبان با پرداخت یک‌باره و استفاده از کلید خودش را می‌خواهد تا هزینه‌ی AI را خودش کنترل کند. (فرض تجاری، وضعیت داده: unconfirmed — در فاز ۱ اعتبارسنجی می‌شود)

## ۷. ارزش پیشنهادی اصلی (Core Value Proposition)

> «برای ادمین کانال تلگرام که هر روز زمان خود را صرف نوشتن و انتشار دستی پست می‌کند، AI Telegram Admin یک افزونه وردپرسی فارسی/RTL است که تولید، تأیید، زمان‌بندی و انتشار محتوا را — بدون نیاز به دانش فنی و با کنترل کامل انسان و بدون هزینه ماهانه — در یک پنل واحد انجام می‌دهد.»

دو ستون ارزش:

1. **صرفه‌جویی در زمان و خروجی منظم:** تبدیل ساعت‌ها کار دستی تولید و انتشار به چند کلیک، با کیفیت ثابت تُن.
2. **کنترل و مالکیت:** انسان تأییدکننده نهایی است؛ کاربر کلید API خودش را می‌آورد (مالک هزینه و داده)؛ روی زیرساخت خودش (وردپرس) اجرا می‌شود؛ بدون قفل‌شدن در سرویس ماهانه‌ی شخص ثالث.

## ۸. USP (نقاط تمایز منحصربه‌فرد)

توجه: مقایسه‌ی ذیل «مزیت محصول» است، نه مقایسه‌ی عددی با رقبا — هر ادعای رقابتیِ عددی (قیمت/فروش/امتیاز) طبق قانون ۱۰ و ۱۲ به فاز ۱ واگذار و «unconfirmed» ثبت می‌شود.

1. **اول فارسی/RTL، نه ترجمه‌ی بعدی:** طراحی UX از ابتدا RTL و فارسی با تن‌های پرامپت فارسی‌محور (Professional، News، Educational و…).
2. **خودمیزبانِ وردپرسی:** روی هاست خریدار نصب می‌شود (بدون سرویس ماهانه و وابستگی به سرور فروشنده)؛ مناسب بازارهایی که خریدار وردپرسی دارد.
3. **Provider-Agnostic (BYOK):** اتصال به هر API سازگار با OpenAI — کاربر ارائه‌دهنده/مدل خودش را انتخاب می‌کند و هزینه‌ی AI را خودش می‌پردازد؛ محصول به هیچ کدوم قفل نیست (مبنای `SPECIFICATION.md:326-352`).
4. **انسان در حلقه:** جریان Draft → Preview → Approve → Publish؛ تمایز کلیدی نسبت به «اتوپست بی‌کنترل».
5. **امنیت از ابتدا:** جداسازی کامل Token/Key از Frontend/URL/لاگ (قانون ۱۳ و ۱۴) به‌عنوان ویژگی محصول، نه ضمیمه.
6. **چرخه کامل در یک محصول:** تولید + زمان‌بندی + صف + انتشار + لاگ در یک پنل، بدون چسباندن چند ابزار.

**فاصله‌ی بازار (Market Gap)** رسماً در پایان فاز ۱ (`SPECIFICATION.md:172-178`) تعیین می‌شود؛ در این فاز فقط چارچوب آن (ستون‌های بالا) آماده شده است.

## ۹. مدل درآمد (Revenue Model)

**پیشنهاد مدل (تصمیم محصول، نه عدد بازار):**

- **فروش لایسنس یک‌باره (One-time License) از طریق مارکت RTL-Theme** — الگوی غالب افزونه‌های وردپرسی در این مارکت‌ها. خریدار با یک پرداخت، افزونه + آپدیت‌های دوره‌ای را دریافت می‌کند.
- **رده‌بندی لایسنس بر اساس Site/Domain** (Regular/Extended) — هم‌راستا با نیاز بازارهای افزونه.
- **درآمد تکمیلی (اختیاری، V2 به بعد):** فروش قالب پرامپت (Template Pack) یا پشتیبانی تمدیدی — فعلاً خارج از اسکوپ فنی.

**وضعیت داده (طبق قوانین ۱۰ و ۱۲):**
- ساختار قیمت‌گذاری عددی: **notCovered** در این فاز.
- تعیین «قیمت پیشنهادی اولیه» رسماً در فاز ۲ (`SPECIFICATION.md:199`) انجام می‌شود و «توصیه نهایی قیمت» در فاز ۲۰.
- هیچ عدد فروش/قیمت رقیب در این سند حدس زده نشده است.

## ۱۰. جایگاهیابی محصول (Product Positioning)

**دسته‌بندی:** ابزار مدیریت و اتوماسیون محتوای تلگرام برای وردپرس (Telegram Content Management & AI Automation Plugin).

**بیانیه جایگاه‌یابی:**

> «برای مدیر کانال و فروشگاه تلگرامی فارسی‌زبان که به‌جای سرویس ماهانه و ابزار پراکنده، یک ابزار یک‌باره‌خریدِ نصب‌شونده روی وردپرس خودش می‌خواهد، AI Telegram Admin راه‌حلی است که کل چرخه تولید تا انتشار را — با هوش مصنوعی قابل‌تنظیم و تأیید انسانی و امنیت توکار — در یک پنل RTL جمع می‌کند؛ برخلاف ربات‌های چتِ صرف، این ابزار از اول برای «مدیریت کانال و محتوا» ساخته شده است.»

**سه محور جایگاه‌یابی:** (۱) خودمیزبان/مالکیت، (۲) فارسی/RTL بومی، (۳) AI قابل‌انتخاب و کنترل‌شونده با تأیید انسان.

## ۱۱. محدوده MVP / V1 / V2

### MVP (نسخه ۱٫۰ — حداقل محصول قابل فروش)

مبنای مرجع: فاز ۸ «MVP پیشنهادی» (`SPECIFICATION.md:397-447`). MVP فقط و فقط همین اسکوپ است:

| حوزه | آیتم‌ها |
| --- | --- |
| Telegram | اتصال Bot، اتصال Channel، مدیریت Channel، ارسال Post، ارسال Image، Preview، Publish |
| AI | اتصال Provider، انتخاب Model، تولید محتوا، بازنویسی، خلاصه‌سازی، تولید عنوان، تولید کپشن، ترجمه |
| Content | Draft، Preview، Edit، Approve، Publish |
| Scheduler | Schedule Post، Queue، Retry، Cancel |
| Dashboard | Channels، Posts، Scheduled Posts، AI Usage، Logs |

شرط پذیرش MVP: «MVP Features = 100%» قبل از Release (قانون Release Gate، `SPECIFICATION.md:1110`). هر چیزی خارج از جدول بالا، در MVP پذیرفته نمی‌شود.

### V1 (تثبیت و بلوغ — پس از MVP پایدار)

پیشنهاد اسکوپ V1 (برگرفته از فازهای ۷، ۹، ۱۰ و ۱۳، به‌عنوان تصمیم محصول، نه بازار):

- **موتور پرامپت کامل:** Templates + Variables + تن‌ها (تمام ۱۰ تُن فاز ۷) + ساخت Template اختصاصی (`SPECIFICATION.md:357-393`).
- **پایداری صف: ۵۰+ پست** با Retry/Resume/Cancel/Crash Recovery/Rate Limit/Timeout/Progress (`SPECIFICATION.md:449-472`).
- **سخت‌سازی امنیتی کامل** مطابق چک‌لیست فاز ۱۰ (`SPECIFICATION.md:475-510`).
- **مدیریت خطای ساخت‌یافته:** Error Code + پیام انسانی + لاگ توسعه + Request ID + استراتژی Retry (`SPECIFICATION.md:827-839`).
- **سازگاری نسخه‌ها:** ماتریس وردپرس/PHP/تلگرام (`SPECIFICATION.md:548-555`).

### V2 (گسترش — پس از اعتبارسنجی بازار)

پیشنهاد اسکوپ V2 (مشروط به تأیید فاز ۱/۲؛ فعلاً در هیچ گِیت الزام‌آور نیست):

- **چند-کاربری و نقش‌ها** (برای تیم‌ها و آژانس — پرسونای P4).
- **گزارش و تحلیل پست‌ها** برای مشتری/مدیر.
- **قالب‌های پرامپت پیش‌ساخته قابل فروش** (Template Pack) — هم‌راستا با مدل درآمد تکمیلی.
- **گسترش یکپارچگی رسانه** (کتابخانه Media و کپشن چندرسانه‌ای پیشرفته).

هر آیتم V2 باید از فیلتر ۱۲.۲ عبور کند؛ صرف «قشنگ بودن» دلیل پذیرش نیست (قانون ۷).

## ۱۲. مرز Feature Creep (تعریف صریح و اجرایی)

### ۱۲.۱ تعریف

Feature Creep یعنی افزودن قابلیتی که (الف) ارزش تجاری آن برای خریدار هدف اثبات نشده باشد، (ب) زمان رسیدن به MVP/V1 را عقب بیندازد، یا (ج) نقطه‌ی کانونی محصول («مدیریت کانال و محتوا» + «تولید → تأیید → انتشار») را رقیق کند. (مبنای قوانین ۷ و ۸: `SPECIFICATION.md:31-32`)

### ۱۲.۲ فیلتر پذیرش هر Feature (Gate قبل از توسعه)

هر Feature پیشنهادی فقط در صورتی وارد اسکوپ می‌شود که **هر چهار** شرط زیر را بگذراند:

1. **ارزش تجاری ثبت‌شده** دارد (کدام پرسونا، کدام درد، چرا حاضر است پول بدهد؟).
2. **به فاز اسکوپ درست تخصیص خورده** (MVP/V1/V2) و MVP را عقب نمی‌اندازد.
3. **به کانون محصول** (تولید محتوا، تأیید، زمان‌بندی، انتشار، تلگرام، AI، امنیت) خدمت می‌کند.
4. **هزینه/فایده توسعه** آن مستند است (زمان زیاد ولی فروش کم = رد؛ `SPECIFICATION.md:193`).

### ۱۲.۳ فهرست صریح «ساخته نمی‌شود» (Out of Scope — از هر نسخه حذف شد)

موارد زیر عمداً و برای همیشه از اسکوپ حداقل تا V2 خارج‌اند؛ افزودن آن‌ها یعنی Feature Creep:

| خروج از اسکوپ | دلیل (تجاری/فنی) |
| --- | --- |
| ربات چت/گفتگوی باز با اعضا | خارج از کانون «مدیریت کانال و محتوا»؛ محصول چت‌بات نیست |
| درگاه پرداخت / فروشگاه داخل تلگرام | دامنه دیگر (تجارت الکترونیک)، ریسک و هزینه امنیتی بالا |
| CRM / قیف عضویت / رشد فالوور | داده و منطق جدا؛ اسکوپ‌خزش کلاسیک |
| ارسال انبوه / دایرکت پیام (Bulk DM) | مخاطره سوءاستفاده/اسپم؛ برخلاف جایگاه محصول |
| اپلیکیشن موبایل Native | پنل وردپرسی موبایل‌فرندلی کافی است؛ هزینه توسعه غیرمتناسب |
| پابلیش به پلتفرم‌های دیگر (اینستاگرام/واتساپ) | خارج از هدف «تلگرام»؛ در صورت تقاضای واقعی به‌صورت Post-V2 ارزیابی مجدد |
| هر Feature خارج از جدول MVP بدون عبور از فیلتر ۱۲.۲ | قانون ۷ و ۸ |

### ۱۲.۴ مکانیزم نگهبانی

- هر آیتم جدید باید به این سند یا `PRODUCT_STRATEGY.md` (فاز ۲) به‌عنوان «Feature Request با فیلتر ۱۲.۲» اضافه شود، نه مستقیم به بک‌لاگ توسعه.
